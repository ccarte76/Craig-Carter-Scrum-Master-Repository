# Scrum Master Portfolio — E-Commerce Checkout Improvement

## Project Overview

This portfolio project demonstrates the practical application of Scrum Master responsibilities through an end-to-end simulated software development project.

The project follows a Scrum team through three Sprints as the team works to improve an existing e-commerce checkout experience.

**Project Type:** Independent Portfolio Project / Scrum Simulation
**Role:** Scrum Master
**Framework:** Scrum
**Duration:** 3 Sprints
**Product:** E-Commerce Checkout Application
**Team:** Simulated Cross-Functional Scrum Team

> **Note:** This is an independent portfolio project created to demonstrate practical Scrum Master skills. It is not professional employment experience.

---

## Product Goal

Improve the e-commerce checkout experience by making payment and order completion easier, clearer, and more reliable for customers.

The team will incrementally deliver improvements including:

* Saved payment methods
* Improved payment error handling
* Shipping address management
* Order confirmation
* Mobile-friendly checkout
* Digital payment options

---

## Scrum Master Responsibilities Demonstrated

Throughout the project, I demonstrate the following Scrum Master responsibilities:

* Facilitating Scrum events
* Supporting effective Sprint Planning
* Facilitating Daily Scrums
* Supporting Product Backlog refinement
* Helping the team create clear User Stories
* Supporting estimation and relative sizing
* Identifying and tracking impediments
* Facilitating impediment resolution
* Supporting the team in achieving Sprint Goals
* Facilitating Sprint Reviews
* Facilitating Sprint Retrospectives
* Supporting continuous improvement
* Tracking Sprint metrics
* Making progress and impediments visible to stakeholders

## Project Structure

### Product Backlog

Contains the Product Backlog, User Stories, priorities, acceptance criteria, and story-point estimates.

### Sprint 1

Documents Sprint Planning, Sprint Goal, Sprint Backlog, Daily Scrum information, impediments, Sprint Review, and Retrospective.

### Sprint 2

Demonstrates how lessons learned from Sprint 1 are applied to improve the team's process.

### Sprint 3

Demonstrates continued delivery, inspection, adaptation, and continuous improvement.

### Metrics

Contains Sprint metrics such as velocity, completed work, and burndown information.

### Final Case Study

Provides an overview of the project and the Scrum Master decisions, actions, challenges, and lessons learned.
